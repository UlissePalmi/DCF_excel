# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

A Python DCF (Discounted Cash Flow) financial model that ingests **S&P Capital IQ `.xls` exports** and outputs a formatted Excel workbook. Currently targeting **Duolingo (DUOL)**. The `old_code/` directory contains an earlier prototype for Amplify Energy Corp. and is a useful xlsxwriter reference only.

## Commands

Python is not on PATH — always use the venv executable:

```bash
# Export model to Excel  (output → finished_models/DUOL_DCF.xlsx)
.venv/Scripts/python.exe excel_export/run.py

# Pass a specific CapIQ file
.venv/Scripts/python.exe excel_export/run.py "Duolingo Inc NasdaqGS DUOL Financials.xls"
```

No build step or test suite. Dependencies (`openpyxl`, `pandas`, `xlsxwriter`, `xlrd`, Python ≥3.12) are declared in `pyproject.toml` and installed in `.venv/`. To add packages use `~/.local/bin/uv.exe add <package>` (no pip in this venv).

## Architecture

### Data Flow
```
CapIQ .xls → CapIQLoader → BaseSchedule subclasses → YPFModel → ExcelExporter → finished_models/{TICKER}_DCF.xlsx
```

### Key Design Pattern: Named-Field Schedules
`CapIQLoader` reads the CapIQ `.xls`, parses each sheet by locating the year-header row ("For the Fiscal Period Ending" / "Balance Sheet as of:"), and builds an internal mapping:

```
(schedule_name, field_key) → {year: float}
```

`BaseSchedule` subclasses call `self._field(key)` which delegates to `loader.field(SHEET_NAME, key)`. **Missing fields return `{}` — never raise `KeyError`.** This lets YPF-era schedules (oil revenue, etc.) remain in the model with no data when used against a non-energy CapIQ file.

Company name and ticker are parsed automatically from the CapIQ header line (`"Duolingo, Inc. (NasdaqGS:DUOL) > Financials > ..."`), so the exporter and output filename require no manual updates when switching companies.

### `DCF_model/` Module Structure
- [DCF_model/loaders/capiq_loader.py](DCF_model/loaders/capiq_loader.py) — `CapIQLoader`; parses CapIQ `.xls`, maps CapIQ row labels → field keys in `_build_fields()`; exposes `field()`, `company_name`, `ticker`; units: IS/BS/CF in Thousands, Key Stats in Millions (scaled ×1000 internally). Additional loaders (other data sources) should be added here.
- [DCF_model/base_schedule.py](DCF_model/base_schedule.py) — base class; all subclasses implement `summary() -> dict` and set `SHEET_NAME`
- [DCF_model/schedules.py](DCF_model/schedules.py) — 14 schedule classes: Oil Revenue, Crude Products Revenue, Other Products Revenue, Downstream Revenue, Total Revenue, Production Costs, S&A Expenses, Income Statement, Cash Flow Statement, Balance Sheet, Fixed Assets (PP&E), Working Capital, Debt & Interest, Shareholders' Equity
- [DCF_model/ypf_model.py](DCF_model/ypf_model.py) — orchestrator; instantiates all 14 schedules, exposes them as named attributes; `model.summary()` returns full nested dict

### `excel_export/` Module Structure
- [excel_export/exporter.py](excel_export/exporter.py) — `ExcelExporter`; reads `model.loader.company_name` / `.ticker` at runtime (no hardcoded names); `ALL_YEARS` / `HIST_YEARS` are module-level constants that must match the loader's year range
- [excel_export/run.py](excel_export/run.py) — CLI entry; auto-finds the CapIQ file in the project root; output filename derived from `model.loader.ticker`

#### Excel Layout Constants (exporter.py)
- `ALL_YEARS` / `HIST_YEARS` — control which years are written and which get blue font + `"A"` suffix
- `COL_DATA_0=7` (col H), `COL_DATA_END = COL_DATA_0 + N_YEARS - 1`
- Historical years → blue font `#0000FF`; projected years → black font + bottom border

#### Critical xlsxwriter Pattern: `center_across`
Write text in the first cell **and blank cells with the same `center_across` format** across the full range. Writing only the first cell is insufficient. See `_center_across()` in `exporter.py` and `center_across_range()` in `old_code/xslx_setup.py`.

### Import Note
Files inside `DCF_model/` use **relative imports without the package prefix** (e.g., `from capiq_loader import CapIQLoader`). This works when running scripts directly. `__init__.py` uses the dotted style for package imports.
